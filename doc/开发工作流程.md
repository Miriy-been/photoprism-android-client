# 开发工作流程

> AI Agent 开发新功能的标准 5 步骤流程。
> 严格按步骤执行，兼顾全局统筹 + 复用 + 少返工。
> 最后更新：2026-06-12

---

## 标准 5 步骤

### 步骤 1：需求拆解 + 全局对齐

**执行者**：AI 与用户协作

1. 用户给出功能需求（或使用 `.trae/documents/需求模板.md`）
2. AI 检索 `doc/模块全景.md` 确认归属模块和依赖关系
3. AI 检索 `doc/复用资产清单.md` 判断是否有现成资产可用
4. AI 检索 `doc/项目总规约.md` 确保符合全局规范
5. **输出**：功能设计方案 + 依赖清单

**检查项**：
- [ ] 功能属于哪个 Feature 模块？
- [ ] 依赖哪些现有的模块/API/组件？
- [ ] 是否有现成模板/通用组件可直接套用？
- [ ] 是否有冲突或影响范围？

---

### 步骤 2：结构 & 类型定义

**执行者**：AI

1. 定义数据类型、数据模型
2. 定义 ViewModel State/Event/Error sealed interface
3. 定义 API 接口或 Repository 方法签名
4. 定义组件结构（Activity + ViewModel + Layout）
5. **用户确认后再进入编码**

**输出示例**：
```kotlin
// 数据类型
data class XxxItem(val id: String, val title: String)

// ViewModel 结构
class XxxViewModel : ViewModel() {
    sealed interface State { ... }
    sealed interface Event { ... }
    sealed interface Error { ... }
}
```

---

### 步骤 3：基于复用资产编码

**执行者**：AI

复用优先级（由高到低）：

```
extension/ → util/ → base/ → common/ → api/
```

1. 优先使用现有扩展函数、工具类、基类
2. 优先使用现有的 API Service
3. 仅编写**当前功能独有逻辑**
4. 遵循 `doc/项目总规约.md` 的所有约束

**规则**：
- 日志：`kLogger(name)` 工厂
- 生命周期：`autoDispose()`
- ViewModel 模式：sealed interface State/Event/Error
- 视图：ViewBinding
- 异步：RxJava 3

---

### 步骤 4：自检 + 架构校验

**执行者**：AI 自查

使用 `.trae/documents/代码审查清单.md` 逐项检查：

- 是否重复造轮子？（检索引复用资产清单）
- 是否符合全局规范？（分层、命名、结构）
- 异常处理是否统一？（ViewModel.Error sealed interface）
- 生命周期管理是否到位？（autoDispose）
- UI 是否符合设计规范？（配色/字体/间距/圆角）

---

### 步骤 5：沉淀复用资产

**执行者**：AI

1. 识别本次功能中可通用的代码
2. 抽离到 `features/common/` 或 `extension/` 或 `util/`
3. 更新 `doc/复用资产清单.md` 中的新增资产
4. 涉及模块依赖变更时，更新 `doc/模块全景.md`
5. 涉及规约变更时，更新 `doc/项目总规约.md`

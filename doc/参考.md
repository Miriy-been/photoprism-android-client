结合AI Agent开发App的场景，从**全局统筹、编码质量、代码复用、快速扩功能**四个维度，给出落地方案，分架构设计、Agent配置、工程规范、流程落地四部分，兼顾实操性。

# 一、先搭「全局统筹」基础：给AI划定顶层规则（核心）

AI能统筹全局的前提是**统一约束+全局上下文**，避免局部编码、架构混乱。

## 1. 固定技术栈&架构规范（强制统一）

提前编写**项目总规约文档**，作为AI Agent的永久上下文，包含：

- 技术栈：框架、语言、UI库、状态管理、接口请求、数据库选型（例：React + TS + Zustand + Axios + Prisma）
- 整体架构：分层架构（前端：页面/组件/工具/路由/接口；后端：控制器/服务/模型/中间件）、目录结构、命名规范、编码风格（ESLint/Prettier规则）
- 设计模式：统一约定常用模式（单例、工厂、组合式、Hook拆分规则等）
- 权限、路由、全局状态、错误处理、日志、埋点**全局通用逻辑**

> 用法：将这份规约设为Agent**系统提示词（System Prompt）**，每次编码强制遵守，保证全局口径一致。

## 2. 全局上下文持久化，避免断档

1. 项目全景文档：记录**模块划分、业务流程图、实体关系ER图、接口清单**，AI随时查阅整体业务，不会只写单功能忽略联动。
2. 版本&模块快照：每次迭代后，让Agent自动更新「项目模块清单」，标注每个模块职责、依赖关系、入口文件。
3. 禁止AI私自新增目录/技术/依赖：所有架构级改动必须先说明、确认后再执行，守住全局架构。

## 3. 拆分「全局角色」，分工统筹

给AI Agent划分角色，各司其职协同：

- **架构Agent**：负责全局设计、模块拆分、依赖管理、评审代码架构（统筹顶层）
- **编码Agent**：负责业务代码、组件、接口实现（执行层）
- **复用维护Agent**：负责通用库、组件、工具函数迭代（沉淀复用资产）
  新功能流程：架构Agent先出方案 → 编码Agent落地 → 维护Agent提取可复用代码。

# 二、提升AI代码编写质量：减少返工，一次成型

## 1. 指令结构化，拒绝模糊需求

给AI的功能需求，固定**标准模板**，信息越全，代码越精准：

```
【功能名称】
【所属模块】（绑定全局架构）
【业务逻辑】（输入、输出、交互、边界场景）
【依赖组件/接口】（引用现有项目能力）
【样式/交互要求】
【必须复用的现有能力】（指定工具、组件、全局方法）
【约束】（禁止新增独立逻辑，统一走全局异常/路由/状态）
```

## 2. 强制「先设计，后编码」

要求AI**先输出伪代码/函数结构/类型定义**，再写实现代码：

1. 第一步：定义TS类型、数据结构、函数入参出参
2. 第二步：拆分函数/组件逻辑，划分职责
3. 第三步：编写业务实现
   从类型和结构兜底，大幅降低逻辑漏洞、重构概率。

## 3. 强校验规则嵌入Prompt

在系统提示词中加入强制约束：

- 必须做参数校验、异常捕获，复用项目全局错误处理
- 代码注释清晰，复杂逻辑拆分小函数
- 遵循项目ESLint规则，不写冗余代码
- 相同逻辑不重复编写，优先调用现有方法

# 三、核心：落地代码复用，实现「少次开发新功能」

复用分为**三层资产**，让AI主动调用，而非重复造轮子，是快速拓展功能的关键。

## 层级1：基础通用层（全项目共用，最高复用）

### 1. 统一封装通用工具库

让AI提前沉淀并固化：

- 工具函数：日期、格式化、校验、加密、数组/对象处理
- 网络请求：统一拦截器、请求头、超时、错误提示（全局Axios/请求类）
- 全局常量：枚举、状态码、文案、路由地址
- 基础Hook/装饰器（前端）、通用中间件（后端）

**规则**：AI编码时，优先从`utils/` `hooks/` `constants/`取能力，禁止重新实现。

### 2. 基础UI组件库（原子组件）

基于UI框架二次封装**项目专属原子组件**：按钮、输入框、弹窗、表格、卡片、加载态、空状态等。

- 统一样式、交互、属性、事件
- AI开发页面/功能时，**只允许使用封装后的组件**，不直接用原生组件
- 新增UI能力统一在基础组件中迭代，全项目同步生效

## 层级2：业务通用层（同模块/同类功能复用）

### 1. 业务公共组件 & 业务Hook

针对重复业务场景抽离：

- 例：用户头像、选择器、列表项、搜索栏、分页组件
- 例：表单校验Hook、列表请求Hook、文件上传Hook

**要求**：每完成一个新功能，AI自动识别**可复用的业务逻辑/组件**，抽离到`components/business/`、`hooks/business/`，并更新复用文档。

### 2. 业务接口聚合

后端统一封装接口服务层，前端封装接口请求函数：

- 同一业务域接口集中管理（如userApi、orderApi）
- 新功能调用已有接口，仅新增独有接口，避免接口混乱

## 层级3：模板层（一键生成同类功能，极致提效）

针对**同质化功能**（列表页、详情页、表单页、弹窗）制作**代码模板**：

1. 由架构Agent提炼标准模板（目录结构、基础代码、样式、路由、状态）
2. 模板固化后，后续新增同类功能，AI直接**基于模板填充业务字段、逻辑**
3. 模板支持变量替换：页面名称、接口地址、表单字段、列表列名

效果：同类功能**一次模板制作，后续1次修改即可完成开发**。

## 4. 复用管理机制（让AI记得复用）

1. **复用资产清单**：维护一份文档，记录所有通用函数、组件、模板、接口，附带使用示例，AI可检索引用。
2. **依赖检查**：编码前AI先检索清单，判断现有能力是否满足，满足则直接调用，不重复编写。
3. **复用迭代闭环**：新功能出现通用逻辑 → 抽离到公共层 → 更新清单 → 后续功能直接使用。

# 四、流程落地：一套标准流程，实现「一次/少次完成新功能」

固定迭代流程，AI严格按步骤执行，兼顾全局统筹+复用+少返工：

### 步骤1：需求拆解 + 全局对齐（架构Agent）

1. 明确新功能归属模块、依赖哪些现有模块/接口/组件
2. 判断：是否有现成模板/通用组件可直接套用
3. 输出：功能设计方案 + 目录规划 + 依赖清单

### 步骤2：结构&类型定义（编码Agent）

输出数据类型、函数签名、组件结构，确认无误再写逻辑。

### 步骤3：基于复用资产编码（核心）

- 优先使用：基础工具 → 业务组件 → 功能模板
- 仅编写**当前功能独有逻辑**，公共逻辑全部调用已有代码

### 步骤4：自检 + 架构校验

AI自查：是否重复造轮子、是否符合全局规范、异常/样式是否统一。

### 步骤5：沉淀复用资产（维护Agent）

识别本次功能中可通用的代码，抽离至公共库、更新复用清单。

# 五、进阶优化：让AI统筹能力再升级

## 1. 引入项目知识库（RAG）

把**规约文档、目录结构、复用清单、接口文档、历史代码**全部接入AI RAG知识库。
AI编码时自动检索项目现有代码、规则、组件，**主动匹配复用项**，不用人工提醒。

## 2. 模块化解耦（从架构上降低拓展成本）

遵循**高内聚、低耦合**：

- 模块之间通过**接口/事件**通信，不直接调用内部逻辑
- 单一职责：一个组件/函数只做一件事
  解耦后，新增功能仅需对接公开能力，不会影响全局，AI也更容易把控边界。

## 3. 版本化复用资产

通用组件、工具库做版本管理，迭代时向下兼容，避免老功能受影响。

# 六、避坑要点

1. 不要让AI无约束自由编码：架构和规范必须前置，否则复用和全局统筹完全失效。
2. 复用不是“强行复用”：差异化过大的逻辑不硬套模板，只抽**共性部分**。
3. 定期清理冗余代码：让AI定期扫描项目，删除废弃函数/组件，保持资产精简。
4. 统一版本与依赖：全局锁依赖版本，避免AI私自升级包导致兼容性问题。

---

### 总结最简落地路线

1. 写**全局规约+目录结构**，设为AI固定Prompt（统筹全局）
2. 分层沉淀：**基础工具→业务组件→功能模板**（代码复用）
3. 固定流程：**设计→结构→编码→抽离复用**（少次开发）
4. 可选升级：接入RAG知识库，让AI自动检索复用资产。

按这套模式落地后，同质化功能基本能做到**1次修改完成**，差异化新功能也能大幅减少代码量与返工。

## 二、架构规范

### 2.1 整体架构

基于 Feature 的模块化组织，每个 feature 自包含完整分层：

```
features/{featureName}/
├── {FeatureName}FeatureModule.kt   # Koin DI 模块
├── data/
│   ├── model/                      # 业务数据模型
│   └── storage/                    # 数据持久化（Repository, Preferences）
├── logic/                          # UseCase / Worker
└── view/
    ├── {FeatureName}Activity.kt    # Activity
    ├── {FeatureName}ViewModel.kt   # ViewModel
    └── model/                      # ListItem, Adapter 等
```

### 2.2 包名规范

- 根包名：`ua.com.radiokot.photoprism`
- 所有包名使用全小写

### 2.3 基类

| 用途 | 基类 | 位置 |
|------|------|------|
| Activity | `BaseActivity` (extends AppCompatActivity) | `base/view/` |
| Dialog | `BaseMaterialDialogFragment` | `base/view/` |
| Repository | `Repository` | `base/data/storage/` |
| 单项 Repository | `SimpleSingleItemRepository<T>` | `base/data/storage/` |
| 集合 Repository | `SimpleCollectionRepository<T>` | `base/data/storage/` |
| 分页 Repository | `SimplePagedDataRepository<T>` | `base/data/storage/` |
| 持久化 | `ObjectPersistence<T>` / `ObjectPersistenceOnPrefs<T>` | `base/data/storage/` |
| 分页模型 | `DataPage<T>` | `base/data/model/` |
| 分页顺序 | `PagingOrder` (DESC / ASC) | `base/data/model/` |

### 2.4 依赖注入

- 使用 Koin 4.1.1
- 每个 Feature 有独立的 `{Name}FeatureModule`，在 `PhotoPrismGallery.onCreate()` 中注册
- ViewModel 通过 Koin 注入，非 `ViewModelProvider.Factory`
- 全局模块：`IoModules`、`RetrofitApiModule`、`EnvModule`、`LocaleModule`、`DateFormatModule` 等
- 参数化工厂使用 `SelfParameterHolder` 基类 + Koin 限定符

### 2.5 API 层

- 定义在 `api/` 目录下，按 domain 分模块
- Retrofit Service 通过 `RetrofitApiModule` 统一注册
- 拦截器链：`HeaderInterceptor` → `SessionAwarenessInterceptor` → `SynchronizedSessionRenewalInterceptor`
- 使用 `SyncCallAdapter` 实现同步调用适配

## 三、编码规范

### 3.1 文件组织

- Feature 内部：`data/` → `view/` → `logic/` 结构
- 跨 Feature 共享逻辑放在 `extension/` 或 `base/`
- 扩展函数按目标类型分文件（如 `View.kt`, `String.kt`, `Rx.kt`）

### 3.2 ViewModel 模式

强制使用 `sealed interface` 三件套：

```kotlin
class XxxViewModel : ViewModel() {
    sealed interface State { ... }           // 视图状态
    sealed interface Event { ... }           // 一次性事件（导航、Snackbar）
    sealed interface Error { ... }           // 可显示的错误类型
}
```

### 3.3 异步与生命周期

- 所有异步操作使用 RxJava 3
- RxJava 订阅必须使用 `autoDispose()` 管理生命周期（支持 `LifecycleOwner` / `ViewModel` / Koin `Scope`）
- 优先使用 `extension/Rx.kt` 中的扩展函数（`toSingle()`, `observeOnMain()`, `retryWithDelay()` 等）

### 3.4 日志

- 使用 `kLogger(name)` 工厂方法获取带实例哈希的日志器
- 日志框架：kotlin-logging + slf4j-handroid

```kotlin
private val log = kLogger("MyClass")
log.debug { "some message" }
```

### 3.5 ViewBinding

- 使用 ViewBinding
- 禁止使用 DataBinding

### 3.6 错误处理

| 层级 | 机制 |
|------|------|
| Repository | `Repository.errors` (PublishSubject) — 统一错误事件流 |
| ViewModel | 订阅 `repository.errors` 后转换为自己的 `Error` sealed interface |
| 自定义异常 | `InvalidCredentialsException`, `SessionExpiredException`, `TfaRequiredException` 等 |

## 四、UI 设计规范

### 4.1 设计方向

iOS × 侘寂风格融合，Material 组件体系不变，注入日系克制的质感。

### 4.2 色彩系统

| 层级 | 色值 | 用途 |
|------|------|------|
| `bg_base` | `#F6F4EF` (和紙) | 页面背景、分组背景 |
| `bg_card` | `#FFFFFF` | 卡片、列表项、对话框 |
| `divider` | `#E8E4DC` | 分割线、边界 (0.5dp) |
| `accent` | `#6B7E8A` (藍鼠) | 选中态、按钮、链接 |
| `accent_light` | `#E8EDF0` | 选中背景、高亮区域 |
| `text_primary` | `#3A3835` (炭灰) | 标题、正文 |
| `text_secondary` | `#8D8882` (暖灰) | 辅助文字、说明 |
| `error` | `#C1665B` (褪紅) | 删除、错误提示 |

### 4.3 禁止项

- 深色模式 — 仅浅色主题
- 渐变 — 纯色块面，无 gradient
- 纯黑 `#000000`
- 高饱和色 (> HSB S=70%)

## 六、关键约束（重要）

### 6.1 绝对禁止

1. **禁止新增技术栈/依赖** — 必须先说明、确认后再执行
2. **禁止私自创建新目录结构** — 所有架构级改动必须先确认
3. **禁止引入 Jetpack Compose**
4. **禁止引入深色模式** — 仅浅色主题
5. **禁止使用 `#000000` 纯黑**
6. **禁止使用渐变**

### 6.2 强制规则

1. 新增通用逻辑必须沉淀到 `extension/` 或 `util/`，不留在 Feature 内
2. RxJava 订阅必须使用 `autoDispose()`
3. ViewModel 必须遵循 `sealed interface State/Event/Error` 模式
4. 编码前必须检索 `doc/复用资产清单.md`，优先使用现有能力
5. 编码前必须检索 `doc/模块全景.md`，确认影响范围
6. 编码后必须自检：是否重复造轮子？是否符合全局规范？
7. 每次迭代后更新 `doc/复用资产清单.md`

### 6.3 兼容性要求

- 支持 TV 遥控器操作
- 仅 `releasePlay` 可构建 Google Play AAB
- 许可证报告自动生成到 `assets/open_source_licenses.html`
